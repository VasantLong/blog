# 花园只从专用 vault 出，知识库不直接发布

知识库（`knowledge-base/`，299 篇）形态上最接近花园条目：原子化词条、`summary/kind/as_of` 前置字段、166 处双链。但它同时装着 `diary/`、`work/`、`personal/` 这些私密面，且住在 Gitea 私有仓、由两端同步维护。

决定：花园的内容源是一个**专用 vault**（花园库），与知识库、与工作库都不共用目录。知识库永不直接作为站点源，将来若要公开，走一条单向导出的链路，把选中的词条**晋升**进花园库，而不是把知识库挂到构建上。

## 后果

- 私密面不进入构建输入，因此不依赖闸门配置的正确性；闸门（`explicit-publish`）退化为第二道保险。
- 知识库与花园之间没有自动同步：一条词条要公开，必须再晋升一次。这是刻意接受的重复，用来换取"知识库怎么改都不会泄漏"。
- 花园仓可以公开（Free 账户的 Pages 只支持公开仓），因为花园库里的一切本来就是给读者看的；半成品必须留在工作库。
